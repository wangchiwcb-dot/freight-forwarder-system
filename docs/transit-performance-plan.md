# 渠道时效页面方案

日期：2026-10-18。状态：页面与静态数据已在本地实现，尚未发布。

## 2026-10-18 用户视角改版

本节记录当前实现，取代下文首版的默认入口和首屏顺序；数据来源、指标算法与原始记录处理保持原口径。

- 默认入口为公司渠道总览，按渠道 × 美西/美中/美东展示典型到仓（中位数）、90% 已到仓记录不超过的天数及样本数。区域汇总描述仓库混合样本，不用于全公司速度排名。渠道/区域缺失和仓库映射待核的记录不进入矩阵，数量明确提示，原始明细仍保留。无样本不代表不提供服务。
- 默认统计窗口为截至最新已记录到仓日近 180 天（当前 2026-03-30 至 2026-09-25），可切换 90 天、各开船年份、全部历史或自定义日期。已有含筛选参数的分享链接若未指定日期，仍按原有全部历史解释；空日期不回退为默认日期。
- “你要发到哪个仓库？”选择仓库后，首屏同时展示该仓所有已知渠道的时效卡片；渠道未填写记录另行提示。切换渠道只改变线路详情，不隐藏同仓其他渠道。比较与详情使用相同日期、区域、组合范围。
- 点击渠道显示线路摘要：典型天数、90% 天数、按实际阈值计算的已到仓占比、样本数量和路线自身最晚到仓日。只在明确仓库与渠道后生成线路报告，避免将全公司混合时效当作线路结论。
- 时效趋势默认折叠、默认按月；周/月趋势和仓库分布共用分页日历。渠道对比图、运输环节、自定义天数占比、仓库分布、原始明细均按需展开。图表钻取期间自动展开相应明细。
- 手机总览通过区域按钮切换可见列，选仓后三个渠道用紧凑卡片比较；更多筛选收起但已生效条件始终在范围栏显示。
- PNG 与打印仍包含当前线路摘要及趋势；导出前自动展开趋势。客户展示隐藏内部分析，保留统计口径与来源日期。数据日期明确指最新已记录到仓日，不是页面提取日期。

验收覆盖默认总览、仓库搜索、低样本/无样本、旧链接、共享时间范围、原始异常记录、历史分页、原生图表交互、手机窄屏、PNG 与打印。

本轮验证：`pnpm check`（94 项测试）、`pnpm build`、17 项时效/主题浏览器用例通过（含失败定位后的定向重跑）。320–1440px 无页面水平溢出；320px 同仓三渠道卡片首屏可见；PNG 带完整趋势，打印为一页 A4。未部署线上。

## 目标与已确认口径

在现有左侧菜单“渠道报价台”下新增“渠道时效”，提供独立页面 `/#/transit`。以实际履约数据回答：这个仓库通常多久到、较慢批次多久到、不同月份是否稳定、延误发生在哪段。

用户已确认：源表“快递交付/送仓日期”均代表实际送达亚马逊仓库。因此主指标统一为“开船 → 实际到仓”，不能表述为入仓收货至送达，也不能表述为亚马逊上架时效。

本期数据从 Excel 离线提取，生成随代码管理的 JSON；页面无需 D1 或新后端接口。现有报价查询继续使用现有接口。

## 源数据初步核验

源文件：`动态时效表 Ultra-26-.17--新增.xlsx`。按要求忽略 `Sheet1` 和 `透视表`。

| 工作表 | 用途 | 初步结果 |
| --- | --- | --- |
| 2025 | 历史明细 | 6,419 条业务记录 |
| 2026数据源 | 新年度明细 | 6,100 条业务记录，另有 152 行仅含公式或非业务内容 |
| 仓库详情 | 仓库、地区、分组及阈值字典 | 现有组合、提醒时效、赔付时效可以复用，但需要保留版本 |
| 仓库组合 | 组合解释 | 辅助仓库分组与展示 |
| 时效看板、时效达成率 | 原展示层 | 重建图表，不作为事实数据来源 |

两张事实表共 12,519 条业务记录，原始仓库代码写法共 257 种，清理首尾空白、换行和大小写后为 215 个代码，不能将这个数字直接宣传为已核实的美国亚马逊仓库数。存在未匹配仓库代码及疑似其他地区记录。原始渠道包括美森、定时达、快船、纽约、萨凡纳、芝加哥，也有空渠道。

有效的开船、交付日期对覆盖开船日期 2025-01-07 至 2026-09-02；已填交付日期截至 2026-09-25。工作表年份与开船年份不同，不能根据 sheet 名称推断业务日期。

初步发现，以下计数可能重叠：

- 84 条交付值缺失或为文字，例如“待预约”“集货”；不解析文字中的日期作为实际到仓日期。
- 12 条到仓日期早于开船日期，集中出现开船年份疑似误填；进入待核，不自动猜测修正年份。
- 64 组“渠道、柜号、开船时间、仓库、到仓时间”相同的候选重复，各多一条。可能为重复录入，也可能有业务含义，须对照后再确定去重。
- 1,070 条记录在组合或提醒/赔付日期相关字段存在 Excel 查找错误。组合匹配失败不代表这条记录的实际运输时效无效。
- 2025 年没有卸船日期；2026 年也有个别缺失。跨年流程拆解应默认使用共同完整的节点。
- 25 条存在节点时间先后倒置。总时效和各段时效应分别判定可用性，不能因为某个中间节点有误而无理由丢弃有效总时效。

实现后指标例子：美森 → ONT8，69 条日期有效的到仓记录，开船日期 2025-01-08 至 2026-09-02；中位数 16 天，P90 为 20 天，63/69（91.3%）在 20 天内到仓，最长 25 天。与初步分析的 68 条相比，仓库写法规范化后识别出一条额外记录。这是历史样本统计，不是对未来的承诺。

## 页面结构

### 首屏：一个清晰结论

沿用项目统一的白色侧栏、浅灰页面、白色卡片和蓝色强调色，具体约定见[前端主题与扩展约定](frontend-theme.md)。图表只统一基础配色与字体，保留原生布局和交互，避免大量饼图、仪表盘和装饰地图。单位统一为天，关键指标保留一位小数或整数，悬浮详情可查看精度。

页面标题“渠道时效”；副标题“美国亚马逊仓库 · 开船至实际到仓”；始终展示数据截至日期和当前筛选范围。

筛选包括仓库搜索、渠道、区域/仓库组合、开船日期范围。优先引导选择具体仓库，再进行同仓渠道对比。总览用于覆盖情况，不混合地区做无条件速度排名。

时间选择支持全部、最近 90/180 天、自定义；若采用相对数据快照的最近 90 天，必须明确写“截至数据日的最近 90 天”，不能误标为相对今天。近期批次尚未全部回填时，显式提示到仓记录覆盖不完整。

四个核心指标：

1. **有效到仓记录数**：显示当前筛选样本数，并可展开独立柜次、缺失和待核数量。
2. **典型时效**：中位数，辅助说明“一半样本在此天数内到仓”。
3. **90% 样本不超过**：P90，对客户比“平均值”更易解释。
4. **时效集中区间**：P10–P90，配合周/月变化解释波动，避免仅凭平均值判定稳定。

首版不自动生成“稳定 98 分”“行业领先”等无依据评分，也不预设好看的准时率。提供“20 天内到仓 63/69，91.3%”这种阈值明确的实测占比。

趋势图不平滑抹掉真实波动，不把缺失月份连接成连续观测。低样本提示规则建议可配置，初版建议分组 n < 10 时弱化结论并显示“样本较少”，不打稳定性标签。这一门槛是产品提示规则，不是统计显著性保证。

环节堆叠如果需要加总到整体，应使用同一完整样本集的分段平均值；不能把各段中位数相加称为整体中位数。2026 年可额外查看到港→卸船→提柜，2025 年缺失的卸船日期不补零。

### 明细与客户沟通

底部折叠明细表，保留仓库、渠道、各节点、实际天数、适用阈值、待核状态和源 sheet/行号。点记录打开节点时间轴；真实较慢记录继续纳入总体指标，只对确认的数据错误采取排除或修正。

支持“客户展示”模式和导出一页 PNG/PDF：仓库、渠道、统计期间、样本数、中位数、P90、趋势图、数据截止时间、指标定义。预览并确认内容后手动发送。内部备注、柜号不出现在对客报告中。

客户描述采用可核验句式：

> 在所选开船期间，美森发往 ONT8 的 69 条日期有效到仓记录中，中位时效为 16 天，63 条在 20 天内到仓，占 91.3%。统计为开船至实际到仓的历史表现。

## 指标定义与统计边界

- 主样本单位暂定“源表的一条到仓记录”，不能将 12,519 行称为独立订单或独立柜数。建立柜次键（规范化柜号 + 开船日期，必要时增加航线），并同时显示独立柜次。缺少订单号时不推算票数。
- 一个柜对应多个目的仓，跨仓汇总不能把这些行当成独立海运航次。海运环节按柜次统计或明确采用到仓记录权重。
- 主图按开船日期归属；跨年依靠日期字段处理。近期未到仓/未回填记录单独展示，不记作 0 天，也不悄悄从达标率分母消失。
- 显示“已到仓样本分布”时，清楚标注仅使用已到仓记录。承诺达成率另行定义批次成熟窗口：未过截止日期的记录待观察；已过截止而无实际日期的记录先标记结果未知，不能在无法区分未送达与漏录时擅自判准时或延误。
- 时间计算保留原始精度，展示值再四舍五入。源数据含少量时分值；自然日差与经过小时/24的差异须在正式导入时统一，禁止混用时区转换引发日期漂移。
- 中位数按排序后中间位置计算；P10/P90 初版建议最近秩法 `ceil(p*n)`，并固定在元数据和测试中。“阈值内占比”另按实际 `days <= threshold` 计数，不能直接将 P90 写成恰好 90.0%。
- 提醒时效与开始赔付时效不同，不直接等同于客户承诺天数。“开始赔付日期”当天是否算超时，以及历年阈值的生效期尚未确认。确认前只展示阈值明确的实测占比；如按当前规则回算，必须标注“按当前规则回看”，不可称为历史承诺达成率。
- 仓库地址及组合字典保留原始值与规范值、映射来源、版本。未知或冲突代码进入待核，不凭近似拼写把仓库合并。地区与渠道也不从空值或相邻行盲目填充。

## JSON 与系统接入

建议新增：

```text
scripts/extract-transit.py             # 指定 sheet 的完整读取、归一化和校验
scripts/validate-transit.mjs            # 数量守恒、类型、日期、聚合一致性校验
public/transit/manifest.json           # 版本、校验和、覆盖范围、文件列表
public/transit/records-2025-<hash>.json # 按开船年份分片的最小到仓记录
public/transit/records-2026-<hash>.json
public/transit/warehouses-<hash>.json   # 经核对的仓库字典
public/transit/rules-<hash>.json        # 阈值定义、版本及生效范围
src/features/transit/TransitPage.tsx
src/features/transit/metrics.ts
src/features/transit/data.ts
```

字段模型：稳定的记录 ID、匿名柜次 ID、渠道、海外仓、船司、航线、目的仓、区域/组合、各实际节点日期、到仓状态、规则引用、原始来源 sheet/行、质量标记。原始文本与校正值分离；派生天数从节点重算，不直接信任缓存的 Excel 公式结果。

元数据区分 `generatedAt`（提取时间）、`dataThrough`（数据覆盖截止时间）、`departureRange`、`sourceSha256`、`schemaVersion`、`metricsVersion`、输入记录数、有效记录数、待核数量和质量报告摘要。文件修改时间不等于数据覆盖时间。不能把最大实际到仓日当成所有批次已完成更新的证明。

原始 workbook、完整柜号和自由文本备注保存在本地忽略目录 `.local/transit` 供核对；仓库中的前端 JSON 只导出所需字段。项目现有静态资源会随网站发布，隐藏界面字段无法阻止下载 JSON，因此对客模式不是数据访问控制。

现有系统是 React 19 + Ant Design + HashRouter。图表统一从 **`@ant-design/charts` 2.6.7** 直接导入 `Line`、`Bar`、`Heatmap` 标准组件，沿用 Ant Design 的布局、筛选、卡片、表格与抽屉。`chartData.ts` 把已核对的周/月和渠道汇总转换成组件所需的数据格式；缺样本传 null，不用分段编号或底层图形拼装实现断线。保留现有主题、尺寸适配和原生提示框的视口边界兼容。聚合包中未使用的 Graphin 关系图依赖仍有 React 18 peer 提示，记录于前端主题文档；页面使用的图表组件经过 React 19 浏览器验证。

趋势图采用标准多系列 `Line`，实线为中位数、虚线为 P90；同仓渠道对比采用标准分组 `Bar`，分别展示中位数与 P90；仓库矩阵采用 `Heatmap`，默认每列一个开船周、格内标注 P90 天数；各环节耗时采用堆叠 `Bar`。不使用 `Base`、`encode`、`children` 拼装图形，不手绘图例，配色来自统一主题。原生悬浮提示挂在独立页面浮层，并限制在可见视口内，避免卡片裁切及屏幕边缘溢出。

数据清洗、筛选与中位数/P90等业务计算独立放在 `metrics.ts`，图表组件接收已计算的数据，仅承担展示。此前的手绘图表示意只用于讨论布局与统计口径，正式实现使用 Ant Design Charts 重新构建。

页面通过 `import.meta.env.BASE_URL` 兼容 GitHub Pages 子路径加载 JSON。菜单选中项、点击跳转、面包屑随路由更新，页头显示“历史时效数据”，不沿用报价页“云端报价库”的状态标签。

进入时效页才加载图表和 JSON；先加载 manifest，再按需要取分片，缓存版本化资源。约 1.25 万条记录适合本地 JSON 与浏览器计算，首版无需为此改动数据库。需要预聚合时保留原始记录作为事实来源，不能平均各组的中位数/P90来拼总体值。

现有报价 Excel 提取脚本对大表有截断策略，不应直接复用其 500 行上限。时效提取应完整处理这两张已指定事实表，并建立行数对账。

## 交付顺序与验收

1. **数据基础**：完整提取两个事实表；生成来源可追溯的 JSON 和质量报告；处理已确认错误；保留未确认问题。数量对账通过，主指标有可复算例子。
2. **第一版页面**：左侧菜单、独立路由、筛选、四个指标、趋势分布、同仓渠道对比、明细抽屉、数据日期和口径说明。加载失败、无数据、样本不足均有状态。
3. **展示增强**：热力表、流程拆解、客户展示和图片/PDF导出。先核对客户报告的数值与筛选一致，再实现下载。
4. **报价联动**：建立经确认的渠道映射后，在报价详情中跳转到相应仓库/渠道的历史时效；不同供应商同名渠道不自动视为相同履约服务。
